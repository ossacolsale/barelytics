# Why Barelytics exists

Barelytics began with a modest question: which pages are being read on a small self-managed website? Many analytics products answer much larger questions and bring hosted services, identifiers, dashboards, and operational choices along with them. Some site owners only need page totals.

The project keeps that measurement small. The default writes daily aggregate counts to local SQLite, avoids persistent visitor identity, and offers optional dimensions only after an administrator makes a clear choice. It is self-hosted, so the operator also carries responsibility for storage, backups, access, updates, and local legal requirements. Barelytics is not a claim that all analytics are harmful or that one technical design settles privacy law; it is a deliberately limited tool for a narrower job.
